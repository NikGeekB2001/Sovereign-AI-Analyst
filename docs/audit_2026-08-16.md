## 4. Аудит плана v2 (sovereign-ai-v2-firecrawl-guide)

### Сильные стороны
- Конкретная метрика: 12 000 → 5 500 токенов/запрос, с реализациями по техникам.
- Дисциплина референсов: «что берём / что избегаем» по 6 проектам.
- Честные антипаттерны: 3 UI, монолит графа, привязка к vLLM.
- Конкретные файлы и требования (6.1–6.2), оценка «2-3 дня до прототипа».

### Слабые места
1. **План писался без верификации базы.** До фиксов система не отвечала вовсе (схема загрузчика ≠ ретриверу). План не содержит шага «проверить, что работает сейчас» → добавлен шаг 0 (верификация + тесты + CI в неделю 1–2, а не в финале).
2. **SafetyHarness «6 уровней» не специфицирован** — какие проверки, коды, политика отказа. Контракт — в MCP_DESIGN.md §5–6.
3. **GLM-4-Flash fallback vs air-gapped** — внешний сервис в миссии on-premise; нужен явный decision и выключатель (ALLOW_EXTERNAL=false по умолчанию).
4. **Firecrawl noauth-лимит 50 req/ч** — упомянут, но нет стратегии: кэш URL→markdown в Qdrant, дедуп, backoff.
5. **Тяжёлые зависимости** (pandas, plotly, paddleocr) для air-gapped — разделить requirements: core / tools / ocr / ui.
6. **Нет контрактов между компонентами** — инструменты, ошибки, стриминг, версии. Закрыто MCP_DESIGN.md.

### Скорректированный roadmap (30 дней)

| Неделя | Было | Стало |

| 1 | Firecrawl MCP | **Тесты + CI + верификация базы** + Firecrawl MCP |
