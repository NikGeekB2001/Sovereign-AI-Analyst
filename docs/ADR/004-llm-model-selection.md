# ADR-004: Выбор LLM моделей (поддержка русского языка, 2026)

## Статус
Принято

## Контекст
Необходимо выбрать open-source языковые модели для мультиагентной системы, работающей в air-gapped среде. Требования:
- Полная поддержка русского языка (морфология, синтаксис, семантика)
- Способность работать с корпоративными документами (юридические, технические, финансовые)
- Лицензия, допускающая коммерческое использование on-premise
- Возможность квантования (AWQ/GGUF) для Consumer GPU
- Актуальность: 2026, рынок РФ (ограничения на импорт, санкции)

## Решение
Использовать **Qwen 2.5/3** как основную модель с **DeepSeek-V3** и **T-lite/Saiga** как альтернативы для специфических задач.

### Стратегия выбора моделей
| Приоритет | Модель | Квантование | Назначение | Обоснование |
|-----------|--------|-------------|------------|-------------|
| Основная | Qwen2.5-32B-Instruct | AWQ 4-bit | Planner, Synthesizer, Analyst | Лучший баланс качества/скорости для русского |
| Резервная | Qwen3-32B-Instruct | AWQ 4-bit | То же при обновлении | Улучшенное reasoning |
| Легковесная | T-lite-7B / Saiga-7B | AWQ/GGUF | Guardrails, классификация | Быстрая фильтрация, PII detection |
| Альтернатива | DeepSeek-V3-671B | AWQ (дистиллят) | Исследование | MoE архитектура, высокое качество |

## Обоснование (Trade-off Analysis)

### Почему Qwen 2.5/3?

**Преимущества:**
1. **Отличная поддержка русского языка:** Обучена на масштабном русскоязычном корпусе, включая юридические и технические документы
2. **Apache 2.0 License:** Свободная лицензия, коммерческое использование без ограничений
3. **Высокое качество reasoning:** Сопоставимо с GPT-4 уровнями на MMLU, GSM8K, HumanEval
4. **Длинный контекст:** До 128K токенов (критично для анализа больших документов)
5. **Function Calling / JSON mode:** Нативная поддержка для MCP интеграции и структурированного планирования
6. **Активное развитие:** Alibaba регулярно выпускает обновления, Qwen 3 вышел в 2025
7. **Оптимизация под квантование:** AWQ/GPTQ версии доступны официально на HuggingFace

**Недостатки:**
- Китайская разработка — потенциальные вопросы безопасности (решается air-gapped развертыванием)
- 32B модель требует >=20GB VRAM (AWQ)

### Почему не Llama 3/4?

**Недостатки для нашего случая:**
1. **Хуже русский язык:** Качество русскоязычной генерации ниже, чем у Qwen
2. **Meta License:** Ограничения на использование для конкурирующих AI-продуктов (>700M MAU)
3. **Меньше оптимизации под русский legal/financial domain**
4. **Модели 70B+ требуют A100/H100** — недоступны в РФ из-за санкций

### Почему не DeepSeek-V3 как основная?

**Преимущества DeepSeek-V3:**
- MoE архитектура (671B параметров, 37B активных) — высокое качество при разумных ресурсах
- Отличное reasoning, конкурентно с GPT-4
- MIT License

**Недостатки для нашего случая:**
1. **Китайская юрисдикция:** Двойные риски безопасности (Китай + санкции РФ)
2. **Огромный размер:** Даже с MoE, 671B модель требует кластер GPU
3. **Меньше production тестов:** Меньше реальных deployment в enterprise РФ
4. **Сложность квантования:** MoE архитектура сложнее в AWQ квантовании
5. **Задержка в поддержке:** Сообщество меньше, медленнее реагирует на баги

### Почему T-lite/Saiga для Guardrails?

**Преимущества:**
1. **Российская разработка:** T-lite (T-Bank/Т-Банк), Saiga (Ilya Gusev) — локальные модели
2. **Оптимизированы для русского:** Лучшая морфология, понимание контекста
3. **Компактные:** 7B-8B — идеально для задач классификации и фильтрации
4. **Быстрые:** 60-100 tok/s на RTX 4090 — минимальная задержка для guardrails
5. **Нет санкционных рисков:** Разработаны в РФ

**Недостатки:**
- Ниже качество для сложного reasoning (по сравнению с 32B моделями)
- Ограниченный контекст (4K-8K токенов)

### Почему не YandexGPT / GigaChat?

**Отклонено:**
1. **Проприетарные:** Нет возможности on-premise развертывания с полным контролем
2. **API-only:** Нарушает требование air-gapped
3. **Vendor lock-in:** Зависимость от конкретного провайдера
4. **Ограниченная кастомизация:** Нельзя настроить промпты и параметры на уровне весов

## Capacity Planning

### VRAM Requirements
| Модель | Параметры | Квантование | VRAM | Throughput (RTX 4090) |
|--------|-----------|-------------|------|----------------------|
| Qwen2.5-32B | 32B | AWQ 4-bit | ~20GB | 15-25 tok/s |
| Qwen3-32B | 32B | AWQ 4-bit | ~20GB | 15-25 tok/s |
| T-lite-7B | 7B | AWQ 4-bit | ~5GB | 60-100 tok/s |
| Saiga-7B | 7B | GGUF Q5 | ~6GB | 50-80 tok/s |
| DeepSeek-V3 (distill) | 671B/37B | AWQ 4-bit | ~2x24GB | 5-10 tok/s |

### Storage Requirements
- Qwen2.5-32B AWQ: ~18GB
- T-lite-7B AWQ: ~4GB
- Saiga-7B GGUF: ~5GB
- **Total:** ~27GB дискового пространства

## Последствия

### Положительные
- ✅ Лучшее качество русского языка среди open-source моделей
- ✅ Apache 2.0 — нет лицензионных ограничений
- ✅ Гибридная стратегия: 32B для reasoning, 7B для скорости
- ✅ Суверенность: все модели работают on-premise, air-gapped
- ✅ Roadmap обновления: Qwen 3 → Qwen 4 без изменения архитектуры

### Отрицательные
- ⚠️ Qwen — китайская разработка (решается air-gapped + аудит весов)
- ⚠️ 32B требует GPU с >=20GB VRAM
- ⚠️ Необходимость хранения нескольких моделей (~27GB)

### Нейтральные
- Модели можно заменять без изменения архитектуры оркестрации
- Квантование можно адаптировать под доступное железо

## Альтернативы рассмотрены
1. **Llama 3/4** — отклонено (хуже русский, лицензия Meta, санкции на GPU)
2. **DeepSeek-V3 (основная)** — отклонено (размер, сложность, двойные риски)
3. **YandexGPT / GigaChat** — отклонено (проприетарные, API-only, vendor lock-in)
4. **Mistral/Mixtral** — отклонено (хуже русский, лицензия для коммерции)
5. **Одна модель 7B** — отклонено (недостаточное качество для сложного reasoning)

## Roadmap обновления моделей

### Phase 1 (Current, 2026)
- Qwen2.5-32B AWQ + T-lite-7B AWQ

### Phase 2 (Q3 2026)
- Миграция на Qwen3-32B при подтверждении качества русского языка
- Оценка DeepSeek-V3 дистиллятов для specialist задач

### Phase 3 (2027)
- Оценка российских моделей нового поколения (Сбер, Яндекс, Т-Банк)
- Возможный переход на полностью суверенный стек моделей
