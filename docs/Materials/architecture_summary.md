# Архитектурное резюме проекта Sovereign-AI-Analyst

## Обзор системы

Sovereign-AI-Analyst - это защищенная, полностью автономная (air-gapped) платформа мультимодального анализа корпоративных знаний с использованием графовых подходов. Проект реализует GraphRAG (Graph Retrieval-Augmented Generation) архитектуру для извлечения и анализа знаний из неструктурированных данных в закрытом контуре.

## Цели архитектуры

- Обеспечить безопасное извлечение знаний из корпоративных документов без выхода в интернет
- Реализовать нейро-символическую архитектуру (GraphRAG) для улучшения точности и уменьшения галлюцинаций
- Обеспечить fine-grained контроль доступа (RBAC) на уровне чанков и узлов графа
- Поддерживать масштабируемость и отказоустойчивость в enterprise среде

## Архитектурные принципы

1. **Security-by-Design**: Безопасность интегрирована на каждом уровне архитектуры
2. **Air-Gapped Operation**: Полностью автономная работа без внешних API
3. **Neuro-Symbolic Integration**: Сочетание нейронных (векторных) и символьных (графовых) методов
4. **Stateful Orchestration**: Поддержка долгосрочных сессий с сохранением контекста
5. **Role-Based Access Control**: Фильтрация данных на уровне чанков/узлов графа

## Архитектурные ограничения

- Запрещено использование внешних LLM API (OpenAI, Anthropic и т.д.)
- Все компоненты должны быть self-hosted
- Обязательна поддержка русскоязычных моделей
- Требуется совместимость с consumer GPU (через квантование моделей)
- Все данные должны фильтроваться по ролям пользователей

## Ключевые компоненты

### 1. LangGraph Orchestrator
- Stateful агент для управления GraphRAG процессом
- Поддержка ReAct, Plan-and-Solve и Multi-Agent паттернов
- Управление памятью и историей сессий

### 2. GraphRAG Retriever
- Гибридный поиск: векторный (в Qdrant) + графовый (в Neo4j)
- Реранжирование результатов с использованием CrossEncoder
- Фильтрация по ролям пользователей

### 3. vLLM Inference Service
- Локальный инференс с поддержкой квантованных моделей (AWQ/GGUF)
- Поддержка русскоязычных моделей (Qwen 2.5/3, DeepSeek-V3)
- KV-cache оптимизации для высокой пропускной способности

### 4. Qdrant Vector Database
- Self-hosted векторная база данных
- Поддержка фильтрации по payload (для RBAC)
- Хранение эмбеддингов документов и чанков

### 5. Neo4j Graph Database
- Self-hosted графовая база данных
- Хранение Knowledge Graph с сущностями и отношениями
- RBAC на уровне узлов и ребер графа

### 6. Security Layer
- Input Guardrails: проверка на prompt injection, PII
- Output Guardrails: проверка на утечки данных, соблюдение политик
- JWT-аутентификация и RBAC

## Архитектурные решения

### Использование LangGraph
- Выбран для реализации stateful агентов вместо линейных цепочек
- Поддерживает сложные паттерны взаимодействия (ReAct, Plan-and-Solve)
- Позволяет сохранять контекст между запросами

### GraphRAG вместо традиционного RAG
- Использование графовой структуры для представления знаний
- Возможность многопрыжкового (multi-hop) рассуждения
- Улучшенная точность за счет семантических связей между сущностями

### Security-by-Design
- RBAC реализован на двух уровнях: Data Plane (в базах данных) и Control Plane (в приложении)
- Проверки на каждом этапе pipeline
- Защита от prompt injection и других атак

## Технологический стек

- **Backend**: FastAPI, LangGraph, PyTorch 2.12
- **LLM Serving**: vLLM с квантованием (AWQ/GGUF)
- **Vector DB**: Qdrant (self-hosted)
- **Graph DB**: Neo4j (Community Edition)
- **Models**: Qwen 2.5/3 (с поддержкой русского языка)
- **Observability**: OpenTelemetry, Prometheus/Grafana

## Архитектурные метрики

- Поддержка consumer GPU (до RTX 4090)
- Время отклика GraphRAG запросов: < 3 секунды (P95)
- Поддержка concurrent пользователей: > 100 (планируется)
- Объем поддерживаемых документов: > 10,000 (векторная часть)
- Уровень безопасности: air-gapped, RBAC на уровне чанков/узлов
