## Слайд 2: Проблемное пространство

**Проблемы традиционных систем анализа знаний:**

- 🔄 **Галлюцинации LLM**: Ответы без опоры на фактические данные
- 📉 **Потеря контекста**: Ухудшение качества при увеличении объема данных
- 🔓 **Безопасность**: Риск утечки конфиденциальной информации
- 🌐 **Зависимость от внешних API**: Невозможность использования в air-gapped средах
- 🇷🇺 **Языковая поддержка**: Ограниченная поддержка русского языка

**Требования к решению:**
- Работа в полностью автономном режиме (air-gapped)
- Поддержка русскоязычных моделей
- Fine-grained контроль доступа (RBAC)
- Устойчивость к галлюцинациям

---

## Слайд 3: Цель и задачи проекта

**Цель:**  
Разработка MVP производственного конвейера (End-to-End Pipeline) для извлечения знаний из неструктурированных данных в закрытом контуре.

**Задачи:**
- Реализовать GraphRAG (нейро-символический подход)
- Обеспечить Security-by-Design (RBAC на уровне чанков/узлов графа)
- Создать архитектуру с использованием LangGraph (Stateful Agents)
- Обеспечить работу без внешних API (air-gapped)

---

## Слайд 4: Архитектурный подход

**GraphRAG (Graph Retrieval-Augmented Generation):**

```
[Документы] → [Chunking & Embedding] → [Qdrant Vector DB]
                                         ↕
[Документы] → [NER & Relation Extraction] → [Neo4j Graph DB]
                                                ↕
                                    [LangGraph Orchestrator]
                                                ↕
                                [vLLM Inference Service]
                                                ↕
                                          [Ответы]
```

**Преимущества:**
- Снижение галлюцинаций за счет графовых связей
- Возможность multi-hop reasoning
- Улучшенная интерпретируемость
- Лучшая фильтрация по ролям

## Слайд 6: C4 Диаграмма контейнеров

**Основные компоненты:**

1. **FastAPI Gateway**: Точка входа с аутентификацией
2. **LangGraph Orchestrator**: Stateful агент для управления процессом
3. **GraphRAG Retriever**: Компонент извлечения с векторным и графовым поиском
4. **vLLM Inference Service**: Локальный инференс
5. **Qdrant Vector DB**: Хранение эмбеддингов с фильтрацией по ролям
6. **Neo4j Graph DB**: Хранение Knowledge Graph
7. **Security Layer**: Input/Output Guardrails

---

## Слайд 7: C4 Диаграмма компонентов (LangGraph Agent)

**Внутреннее устройство агента:**

- **Planner**: Разбиение сложной задачи
- **Memory Module**: Short-term (History) / Long-term
- **Retriever**: Векторный и графовый поиск, гибридный ретривер
- **Reranker**: CrossEncoder для переоценки релевантности
- **Prompt Manager**: Управление шаблонами промтов
- **Tool Interface**: VectorSearch, GraphSearch, WebSearch
- **Output Guardrails**: Проверка ответа на утечку данных

## Слайд 9: Безопасность (Security-by-Design)

**Уровни защиты:**

1. **Network Layer**: Air-gapped deployment
2. **Application Layer**: JWT authentication, RBAC
3. **Data Layer**: Role-based filtering in DBs
4. **Inference Layer**: Input/Output guardrails

**Input Guardrails:**
- Проверка на prompt injection
- Фильтрация PII
- Проверка на попытки обхода безопасности

**Output Guardrails:**
- Проверка на утечки данных
- Проверка на соблюдение политик
- Фильтрация по ролям пользователей

## Слайд 11: Реализация GraphRAG

**Процесс обработки запроса:**

1. **Получение запроса** → API Gateway (с аутентификацией)
2. **Извлечение контекста** → Гибридный поиск (векторный + графовый)
3. **Реранжирование** → CrossEncoder для уточнения релевантности
4. **Формирование промта** → Prompt Manager
5. **Генерация ответа** → vLLM с локальной моделью
6. **Проверка безопасности** → Output Guardrails
7. **Возврат результата** → Потоковая передача пользователю
