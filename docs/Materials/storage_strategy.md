# Стратегия хранения данных проекта Sovereign-AI-Analyst

## Обзор

Данный документ описывает стратегию хранения данных в системе Sovereign-AI-Analyst, включая архитектуру хранения, типы данных, политики безопасности и управления жизненным циклом.

## Типы хранимых данных

### 1. Векторные данные (Qdrant)
- **Тип**: Эмбеддинги документов и чанков
- **Формат**: Float32 вектора фиксированного размера
- **Объем**: ~1KB на чанк (включая метаданные)
- **Хранение**: Векторная база данных Qdrant
- **Срок хранения**: Не ограничен (пока не удалено пользователем)

### 2. Графовые данные (Neo4j)
- **Тип**: Сущности, отношения, атрибуты
- **Формат**: Узлы и ребра графа с свойствами
- **Объем**: ~500 байт на узел/ребро
- **Хранение**: Графовая база данных Neo4j
- **Срок хранения**: Не ограничен (пока не удалено пользователем)

### 3. Метаданные документов
- **Тип**: Информация о документах, владельцы, права доступа
- **Формат**: JSON/Structured
- **Объем**: ~10KB на документ
- **Хранение**: PostgreSQL (или встроенные метаданные баз)
- **Срок хранения**: 7 лет (в соответствии с требованиями)

### 4. Логи и аудит
- **Тип**: Запросы пользователей, ответы системы, ошибки
- **Формат**: Structured logs
- **Объем**: ~1KB на событие
- **Хранение**: Elasticsearch/PostgreSQL
- **Срок хранения**: 1 год (по требованиям безопасности)

### 5. Сессии и состояния
- **Тип**: Состояния LangGraph агентов, история взаимодействий
- **Формат**: JSON/YAML
- **Объем**: ~100KB на сессию
- **Хранение**: Redis/PostgreSQL
- **Срок хранения**: 30 дней (после чего архивируется)

## Архитектура хранения

### Многоуровневая архитектура

```
┌─────────────────────────────────────────────────────────┐
│                    Application Layer                    │
├─────────────────────────────────────────────────────────┤
│  LangGraph States  │  Session Cache  │  Temp Storage   │
├─────────────────────────────────────────────────────────┤
│           Service Layer (Microservices)                 │
├─────────────────────────────────────────────────────────┤
│     Qdrant (Vector)    │    Neo4j (Graph)              │
├─────────────────────────────────────────────────────────┤
│         Core Storage Layer                              │
├─────────────────────────────────────────────────────────┤
│    PostgreSQL (Meta)   │   Redis (Cache)               │
├─────────────────────────────────────────────────────────┤
│                    Physical Storage                     │
└─────────────────────────────────────────────────────────┘
```

### Уровни хранения

#### Hot Storage (Быстрый доступ)
- **Назначение**: Активные данные, часто используемые
- **Технологии**: Redis, SSD массивы
- **Характеристики**: Высокая скорость доступа, высокая стоимость
- **Срок хранения**: До 30 дней

#### Warm Storage (Средний доступ)
- **Назначение**: Данные средней активности
- **Технологии**: Qdrant, Neo4j на SSD
- **Характеристики**: Средняя скорость доступа, средняя стоимость
- **Срок хранения**: До 1 года

#### Cold Storage (Архив)
- **Назначение**: Редко используемые данные
- **Технологии**: HDD массивы, object storage
- **Характеристики**: Низкая скорость доступа, низкая стоимость
- **Срок хранения**: До 7 лет

## Безопасность хранения

### Шифрование данных

#### At-Rest (на диске)
- **Механизм**: AES-256 шифрование
- **Уровень**: Файловая система, базы данных
- **Ключи**: HSM или secure key vault

#### In-Transit (в процессе передачи)
- **Механизм**: TLS 1.3
- **Уровень**: Между сервисами, клиент-сервер

#### In-Use (в процессе использования)
- **Механизм**: Confidential Computing (где возможно)
- **Уровень**: Временные данные в памяти

### Контроль доступа

#### RBAC на уровне хранения
- **Принцип**: Role-Based Access Control на уровне чанков/узлов
- **Реализация**: Фильтрация на уровне запросов к базам данных
- **Политики**: Динамическая оценка политик доступа

#### Аудит доступа
- **Журнал**: Все попытки доступа к данным
- **Хранение**: 1 год в зашифрованном виде
- **Мониторинг**: Real-time алертинг на аномалии

## Резервное копирование

### Типы резервных копий

#### Full Backup (Полные)
- **Частота**: Еженедельно
- **Объем**: Все данные системы
- **Хранение**: 4 недели
- **Место**: Отдельный зашифрованный том

#### Incremental Backup (Инкрементные)
- **Частота**: Ежедневно
- **Объем**: Измененные данные с последней полной копии
- **Хранение**: 1 неделя
- **Место**: Локальный том

#### Transaction Log Backup (Лог транзакций)
- **Частота**: Каждые 15 минут
- **Объем**: Логи транзакций
- **Хранение**: 3 дня
- **Место**: Быстрый доступ (SSD)

### Политики хранения резервных копий
- **3-2-1 Rule**: 3 копии, 2 разных носителя, 1异地
- **Шифрование**: Все копии шифруются AES-256
- **Верификация**: Еженедельная проверка целостности

## Управление жизненным циклом данных

### Классификация данных
- **Public**: Общедоступные данные (уровень 1)
- **Internal**: Внутренние данные (уровень 2)
- **Confidential**: Конфиденциальные данные (уровень 3)
- **Secret**: Секретные данные (уровень 4)

### Политики истечения
- **Public**: Не ограничено
- **Internal**: 5 лет, затем архивация
- **Confidential**: 7 лет, затем безопасное удаление
- **Secret**: По решению комитета безопасности

### Архивация
- **Триггер**: По истечении срока хранения
- **Процесс**: Перенос в cold storage
- **Метаданные**: Сохраняются для поиска

## Производительность хранения

### SLA для хранения
- **Доступность**: 99.9% для hot storage
- **Время отклика**: <10ms для векторных запросов
- **Пропускная способность**: 1000 запросов/сек
- **Время восстановления**: RTO < 4 часа

### Оптимизация
- **Индексация**: Специализированные индексы для каждого типа данных
- **Кэширование**: Многоуровневое кэширование
- **Компрессия**: LZ4/Zstd для холодных данных
- **Дедупликация**: На уровне блоков для векторных данных

## Мониторинг и управление

### Ключевые метрики
- **Использование дискового пространства**
- **Время отклика запросов**
- **Количество операций ввода-вывода**
- **Уровень ошибок ввода-вывода**
- **Целостность данных**

### Алертинг
- **Низкое место на диске**: <10% свободно
- **Высокая задержка**: >100ms для hot storage
- **Ошибки ввода-вывода**: >0.1% от общего числа операций
- **Нарушения безопасности**: Попытки несанкционированного доступа

## Compliance и регулирование

### Соответствие требованиям
- **GDPR**: Право на удаление данных
- **SOX**: Хранение финансовых данных
- **ISO 27001**: Управление информационной безопасностью
- **Российское законодательство**: Хранение персональных данных

### Политики соответствия
- **Data residency**: Данные хранятся только на территории РФ
- **Retention periods**: Следование установленным срокам хранения
- **Right to deletion**: Поддержка удаления данных пользователем
- **Consent management**: Управление согласиями на обработку
