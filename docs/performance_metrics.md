# Метрики производительности Sovereign-AI-Analyst

Два уровня метрик:

1. **Качество RAG (RAGAS-стиль)** — насколько ответы точны, релевантны и опираются
   на найденные документы. Считаются автоматически judge-моделью (Ollama/vLLM).
2. **Производительность системы** — скорость, токены, кэш, ошибки, стоимость.

Реализация: `backend/evaluation/` (без зависимостей ragas — лёгкий аналог на
существующем стеке). Запуск и золотой набор — см. ниже.

---

## 1. Метрики качества RAG (RAGAS-стиль)

| Метрика | Смысл | Формула | Диапазон | Цель |
|---|---|---|---|---|
| **Faithfulness** | Верность ответа контексту: доля утверждений ответа, подтверждённых найденными документами | подтверждённые утверждения / все утверждения | 0–1 | ≥ 0.85 |
| **Answer Relevancy** | Релевантность ответа вопросу: средний косинус между эмбеддингом вопроса и вопросами, сгенерированными из ответа | mean(cos(emb(q), emb(q_i))), q_i — 3 вопроса из ответа | 0–1 | ≥ 0.7 |
| **Context Precision** | Насколько релевантные фрагменты стоят высоко в выдаче ретривера | Σₖ precision@k · rel_k / Σ rel (формула RAGAS) | 0–1 | ≥ 0.7 |
| **Context Recall** | Полнота контекста: доля утверждений эталонного ответа, покрытых найденными документами | покрытые утверждения эталона / все утверждения эталона | 0–1 | ≥ 0.7 |
| **Hallucination Rate** | Доля выдуманного: утверждения ответа без опоры в контексте | 1 − faithfulness | 0–1 | ≤ 0.15 |

Интерпретация:

- **Faithfulness < 0.85** — LLM галлюцинирует: смотреть промпты синтеза,
  ограничение контекста, температуру; на CPU-стеке (qwen2.5:7b) норма ниже,
  чем на vLLM-моделях уровня 32B.
- **Context Recall низкий** — ретривер теряет нужные документы: проверять
  эмбеддинг-модель, top_k, порог min_score, разметку access_level (RBAC
  может скрывать релевантные internal-документы для роли «куратор»).
- **Context Precision низкий** — в выдаче много мусора: реранкер, top_k,
  качество чанков.

## 2. Метрики производительности системы

| Метрика | Где считается | Целевое значение | Триггер алерта |
|---|---|---|---|
| **Время ответа (p50/p95)** | API-слой (`execution_time_ms`) | p50 ≤ 30с, p95 ≤ 120с (CPU-стек Ollama) | p95 > 180с |
| **Токены на запрос** | Langfuse span / LLM-клиенты | ≤ 5 500 | > 8 000 |
| **Cache hit rate** | кэш ответов `/chat` | ≥ 20% на повторяющихся вопросах | < 5% при повторах |
| **Ошибки по SOV-\*** | SOV-1xxx..5xxx (см. docs/mcp_design.md) | ошибки валидации — 0%; SOV-5xxx — ≤ 1% | рост SOV-5xxx > 2% |
| **Retrieval latency** | `retrieval_ms` в отчёте оценки | ≤ 1 500 мс (эмбеддинг + Qdrant) | > 3 000 мс |
| **Стоимость/запрос** | токены × тариф модели (vLLM) | на CPU-стеке — условно 0 | — |
| **Throughput** | запросов/мин | 1–2 (7b на CPU, один GPU-слот не требуется) | — |

## 3. Автооценка: как запускать

```bash
# 1. Стек поднят (Neo4j, Qdrant, Ollama) и данные загружены (data/load_to_dbs.py)
# 2. Оценка полным конвейером в процессе (быстрее):
python -m backend.evaluation.run_evaluation \
    --dataset backend/evaluation/test_dataset.jsonl \
    --mode graph --limit 3 --role куратор

# 3. Оценка через запущенный API (истинный E2E):
python -m backend.evaluation.run_evaluation \
    --dataset backend/evaluation/test_dataset.jsonl \
    --mode api --api-url http://localhost:8000
```

Результат: JSON + HTML-отчёт в `backend/evaluation/reports/` (по каждой метрике:
значение, вопросы, latency).

**Золотой набор** — `backend/evaluation/test_dataset.jsonl` (question +
ground_truth). Расширяется под новые домены; ground_truth обязателен только
для context_recall.

## 4. Ограничения и честная оценка

- **Judge = qwen2.5:7b** — метрики шумные, между прогонами возможен разброс
  ±0.05–0.1. Для стабильных прод-замеров нужен отдельный judge (Qwen2.5-32B/vLLM)
  или подключение библиотеки ragas / DeepEval с API-моделью.
- **Ответы оцениваются по контексту ретривера**, а не по всем данным графа
  (Neo4j-часть конвейера в faithfulness не учитывается — это документированное
  упрощение: context_* метрики считаются по Qdrant-выдаче).
- **CI**: чистые функции метрик (формулы, парсинг JSON judge) покрыты
  unit-тестами и работают без БД/LLM (`tests/test_unit_ragas_metrics.py`).
  Полный прогон — вручную/по расписанию на поднятом стеке (нужны Ollama+БД).
- CPU-стек: 6 judge-вызовов на вопрос ≈ +2–4 мин к времени прогона.
